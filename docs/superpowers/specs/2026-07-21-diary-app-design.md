# 일기장 웹앱 설계

## 배경
사용자가 `C:\claude\일기장` 폴더에서 개인용 일기장 웹앱을 새로 만들기로 함. 목표는 단순히 일기를
쓰는 것보다, **검색과 회고(과거 기록을 다시 보는 경험)** 에 무게를 둔 도구를 만드는 것.

## 목표
- 로컬에서 실행하는 1인용 웹앱
- 매일 부담 없이 짧게 기록할 수 있을 것
- 시간이 지난 뒤 과거 기록을 다시 만나는 경험(회고)을 핵심 가치로 둘 것

## 범위 밖 (초기 버전에서 제외)
- 다중 사용자 / 로그인 인증
- 클라우드 동기화, 배포(외부 호스팅)
- 모바일 전용 UI 최적화

## 기술 스택
- **백엔드/프론트엔드:** C# + Blazor Server (ASP.NET Core)
  - 사용자가 전공 팀 프로젝트 2건을 모두 C#으로 진행한 경험이 있어, 새 언어/프레임워크 학습 부담 없이
    프론트엔드까지 한 언어로 처리 가능하다는 점에서 선택.
- **데이터베이스:** SQLite 단일 파일(`diary.db`), EF Core로 접근
- **이미지 저장:** 로컬 파일시스템(`wwwroot/uploads/`)에 저장하고 DB에는 경로만 기록
- **실행 방식:** `dotnet run`으로 로컬에서 실행, 브라우저로 접속

## 데이터 모델
```
DiaryEntry
- Id (PK)
- Date (날짜, 시간 포함 — 정렬/식별용. 유니크 제약 없음: 하루 여러 개 작성 가능)
- Content (본문, 필수)
- Mood (nullable, int 1~5 — 선택 입력)
- CreatedAt

Tag
- Id (PK)
- Name (unique)

DiaryEntryTag (다대다 조인 테이블)
- DiaryEntryId (FK)
- TagId (FK)

DiaryImage
- Id (PK)
- DiaryEntryId (FK)
- FilePath (wwwroot/uploads/ 기준 상대 경로)
```

## 핵심 기능

### 1. 홈 화면 — 회고
- 오늘을 기준으로 여러 시간 단위(계단식)로 과거 기록을 자동으로 보여줌:
  - **7일 전** (= 저번주 같은 요일, `오늘 - 7일`)
  - **1개월 전** (같은 날짜, 예: 6/21 → 5/21)
  - **1년 전, 2년 전 …** (같은 월/일)
- 각 시간 단위에 해당 날짜의 기록이 있을 때만 표시하고, 없으면 그 항목은 생략 (빈 문구 없이).
- 이렇게 계단식으로 두는 이유: 1년 치 기록이 쌓이기 전(특히 사용 초기 몇 주~몇 달)에도 "7일 전",
  "1개월 전" 회고는 바로 채워져서 회고 기능이 처음부터 의미 있게 동작함.
- 이 화면이 앱을 열었을 때 기본으로 보이는 진입점.

### 2. 새 일기 작성
- 입력 필드: 날짜(기본값 오늘, 수정 가능) · 본문(필수) · 태그(자유 입력, 다중) ·
  기분(선택, 5단계 이모티콘) · 이미지 첨부(선택, 여러 장 가능)
- 제목 필드는 없음 — 날짜(+같은 날 여러 개인 경우 작성 순서)로 항목을 구분.

### 3. 목록/타임라인
- 날짜 역순(최신순) 목록.
- 각 항목: 날짜·시간, 본문 일부 미리보기, 태그, 기분 아이콘.

### 4. 검색
- 본문 텍스트 검색 (부분 일치).
- 태그 필터 (하나 이상 선택 시 AND/OR는 구현 단계에서 단순하게 OR로 시작).
- 검색과 목록 화면은 같은 화면에서 필터 형태로 결합해도 되고 별도 화면이어도 됨 — 구현 계획 단계에서
  세부 결정.

## 이미지 처리 관련 제약
- 업로드 용량 제한: 장당 5MB 정도로 제한 (서버 측에서 검증).
- 지원 형식: 일반적인 이미지 포맷(jpg, png, gif, webp) 정도로 제한.

## 에러 처리
- 본문이 비어 있으면 저장 불가 (필수 필드 검증).
- 이미지 업로드 실패(용량 초과, 형식 불일치) 시 사용자에게 명확한 오류 메시지 표시, 다른 필드 입력은
  유지.
- 존재하지 않는 항목 조회/삭제 시도 시 사용자에게 알리고 목록으로 안내.

## 테스트 방향
- 데이터 모델(DiaryEntry, Tag, Image) CRUD에 대한 단위 테스트.
- 계단식 회고(7일 전/1개월 전/N년 전) 조회 로직 — 월 경계, 윤년(2/29), 데이터 없는 경우 등 엣지 케이스 테스트.
- 텍스트 검색 및 태그 필터 결과 검증.

## 미해결 사항 (구현 계획 단계에서 결정)
- 검색·목록 화면을 하나로 합칠지 분리할지.
- 태그 다중 선택 시 AND/OR 필터 로직의 구체적 동작.
